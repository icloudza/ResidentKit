# 设备自动接入

装好安装包的设备自动向服务器申请接入，管理员在控制台弹窗里点「同意」即可，手机上不用填任何东西。

## 1. 流程

1. **打包时写入服务器**：`scripts/package-rootless.sh` 读取发布者本机的 `~/.config/residentkit/server.env`（不在仓库里），把服务器地址和证书指纹编进安装包：

   ```sh
   RK_SERVER_URL=wss://域名/rk
   RK_SERVER_PIN=          # 域名证书留空
   ```

   域名证书（Nginx + certbot）由受信任 CA 签发，设备按系统校验，不需要指纹。
   只用 IP + 自签证书时才写 `RK_SERVER_PIN`（`server/bin/rk-release pin cert.pem` 输出，逗号分隔可写公钥指纹和证书指纹）；
   公钥指纹在续期沿用同一把私钥时不变。

   没有这个文件时打出的包需要在 App「服务器连接」里手动填地址和令牌（旧方式仍可用）。

2. **设备申请**：daemon 的 `net.enroll` 模块在「有地址、无令牌」时运行。首次生成设备密钥（ECDSA P-256，私钥只存在设备的 `modules/net.enroll/device.key`，仅 root 可读），向 `POST https://域名/enroll` 提交设备 ID、名称、型号、版本和公钥。域名证书按系统校验，自签证书按打包写入的指纹校验。

3. **管理员批准**：控制台任意页面弹出「新设备请求接入」，显示设备名、型号、来源 IP 和 6 位配对码（公钥指纹，手机 App「服务器连接」里显示同一个）。点「同意」或「拒绝」。

4. **领取令牌**：设备每 5 秒问一次；同意后的下一次请求返回为这台设备签发的令牌，交给 `net.link` 立即连接。之后与手动配置的设备完全一样（OTA、远程配置、指令）。

## 2. 安全

- 每个请求都带设备私钥对 `residentkit-enroll\nv1\n{设备 ID}\n{公钥}\n{时间戳}\n` 的签名，时间戳误差 ≤ 5 分钟。令牌只发给持有该私钥的设备，别人截获或伪造请求拿不到。
- 是否放行由管理员决定；安装包里不含任何密钥，外泄也只能「申请」。
- 每台设备一个独立令牌，可单独吊销。被吊销的设备连接时，服务器以关闭码 4401 告知，
  设备随即丢弃令牌、重新申请接入，等管理员再次批准；这类连接不计入 IP 封禁。
- 已有设备在线的 IP 不会被封禁（多台设备共用一个出口 IP 时，一台出错不会让全部断线）。
- 防刷：
  - 签名或格式错误计入网关封禁（与鉴权失败共用）。
  - 每个 IP 每分钟最多 30 次请求，每小时最多发起 20 个新申请。
  - 同时待批准的申请最多 20 个，10 分钟没处理就作废。
  - 被拒绝的设备 1 小时内不再弹出。
- 设备丢失令牌（如重装）但密钥还在、令牌未吊销时，再次申请会自动换发新令牌并吊销旧的，无需重新批准。

## 3. 状态

| 设备端（`net.enroll` status） | 含义 |
|---|---|
| `requesting` | 正在发送申请 |
| `pending` | 等待控制台批准，附 `code` |
| `done` | 已有令牌 |
| `rejected` | 被拒绝，稍后重试 |
| `error` | 网络或服务器错误，30 秒起指数退避（最多 5 分钟） |

服务端 `enrollments` 表：`pending` → `approved`（同意）→ `completed`（令牌已发出），或 `rejected` / `expired`。审批记入审计日志（同意设备接入 / 拒绝设备接入）。
